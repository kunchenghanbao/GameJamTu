# 肉鸽玩法执行交接

这份文档给下一次开发对话直接执行。目标是先做一个可运行的垂直切片，再扩展随机路线和内容。除非用户另有指示，按本文顺序实施。

## 1. 已确定的产品规则

- 肉鸽是独立玩法入口，普通关卡流程不创建 Run。
- 首版采用纯局内 Run：装备、技能、被动、道具、金币和临时 HP/SP 默认不带回主线。
- 每击杀一个敌方单位，Run 等级 +1；只计一次，召唤物/反伤/环境击杀按归属判定。
- 每次有效击杀生成三张候选卡，使用 `rewardQueue` 排队，在当前行动、反击、死亡动画和 AI 流程完成后逐组展示。
- 卡牌类型包括武器、装备、主动技能、被动技能、消耗品和即时强化。
- 推荐路线：小地图 A -> 小地图 B/商人/休整 -> 大型 Boss；Boss 前节点可概率替换为商人或休整。
- 普通小地图之间默认继承 HP/SP；Run 开始时临时关闭 `WorldData.fullStateWhenBattleStart`，所有退出路径恢复原值。
- 新 Run 扫描当前主干登记的技能、装备、职业和角色；进行中的 Run 使用创建时锁定的内容版本。

## 2. 当前项目事实和关键入口

### 2.1 关卡选择界面

- 现有关卡选择 UI 数据：`asset/json/ui/data/ui38.json`。
- UI 注册列表：`asset/json/ui/uiList.json`，名称为“演示-关卡选择”。
- 系统基类在 `Game/system/UIRuntime.ts` 中生成 `GUI_38`，项目层目前没有 `GUI_38.ts`。
- UI 38 目前有四张关卡按钮和商店/菜单/缩放/作弊按钮。
- 肉鸽入口建议作为第五张图片卡片加入 UI 38；不要新建一个完全独立的主界面入口。
- 需要新建项目层 `GUI_RogueEntry` 或直接给 UI 38 增加肉鸽按钮事件适配。优先保留 UI 38 的普通关卡行为不变。

### 2.2 战斗击杀与奖励

- 死亡入口：`Game/game/project/battle/GameBattleData.ts` 的 `die`。
- 掉落收集：`dropRecordByDie`，会累计金币、经验、道具、装备。
- 主线奖励写入：`calcHitReward`，会调用 `increaseGold`、`increaseExpByIndex`、`changeItemNumber`、`addEquipByInstance`。
- 肉鸽必须在这些主线写入之前判断 `RogueRunManager.active`，否则会污染主线。
- 胜负收口：`Game/game/project/battle/GameBattle.ts` 的 `checkBattleIsComplete`，设置结束状态后执行公共事件 `14022`。
- 如果复用 `14022`，必须增加肉鸽幂等标记，避免同时执行普通结算和肉鸽结算。

### 2.3 场景切换

- 场景加载、离场事件、玩家对象保留和新场景事件由 `Game/game/GameGate.ts` 统一处理。
- 现有场景列表：`asset/json/scene/sceneList.json`，当前已有普通战役、Boss、野外和城镇场景。
- 肉鸽节点不要绕过 `GameGate`，节点选择只决定目标 `sceneID` 和节点类型。
- 新肉鸽地图应使用独立场景 ID/事件，避免触发主线剧情开关。

### 2.4 存档扩展

- 项目已有 `SinglePlayerGame.regSaveCustomData` 扩展模式，参考：
  - `Game/game/project/battle/GameBattle.ts` 的 `GameBattle` 自定义存档。
  - `Game/game/project/scene/ProjectClientScene.ts` 的 `Scene` 自定义存档。
- Run 应注册独立 key，例如 `RogueRun`，不要把临时状态混入普通角色或场景字段。
- 存档至少支持：新建、继续、失败、放弃、普通存档读取时清理、版本不兼容降级。

### 2.5 编译登记

- `Game/tsconfig.json` 使用显式 `files` 列表。
- 每个新增 `.ts` 必须加入 `Game/tsconfig.json`，否则编辑器和构建不会编译它。
- UI 数据 JSON、图片和场景资源不等于脚本已注册，二者都要完成。

## 3. 必须实现的脚本边界

建议新建并保持职责分离：

| 脚本 | 第一版职责 |
| --- | --- |
| `RogueRunState.ts` | 可序列化 Run 数据、版本、种子、节点、临时背包、奖励队列 |
| `RogueRunManager.ts` | `active`、创建/继续/退出、全局规则快照恢复、场景节点切换 |
| `RogueKillProgress.ts` | 监听死亡、击杀归属、唯一 ID 去重、Run 等级 +1 |
| `RogueRewardPool.ts` | 动态扫描主干数据、标签过滤、品质权重、职业限制、三卡生成 |
| `RogueRewardResolver.ts` | 只写 Run 临时背包/副本，确认后发放，重复转化 |
| `RogueSceneDirector.ts` | 节点类型初始化、敌人组、商人/休整/Boss 场景 |
| `RogueSaveAdapter.ts` | `SinglePlayerGame` 注册、版本迁移、坏数据降级 |
| `GUI_RogueEntry.ts` | 开始/继续/放弃、队伍预览、规则确认 |
| `GUI_RogueMap.ts` | 节点选择和 Run 状态显示 |
| `GUI_RogueReward.ts` | 三卡展示、二次确认、奖励队列、触屏/虚拟 A/B |
| `GUI_RogueResult.ts` | 结算展示并调用管理器清理，不能自己清理全局状态 |

不要把这些分支直接堆进 `ProjectGame.ts`、`GameBattle.ts` 或 `ProjectPlayer.ts`。核心类只增加最小事件钩子。

## 4. 数据契约

### 4.1 卡牌/主干内容标签

新增技能、装备、职业、角色沿用现有数据库登记，并通过肉鸽元数据决定是否进入卡池：

```text
rogueEnabled
rogueType
rogueWeight
rogueMinFloor
rogueMaxFloor
rogueAllowedClassIDs
rogueDuplicatePolicy
rogueBalanceGroup
```

未标记内容不进入肉鸽卡池，但不能影响普通关卡。

### 4.2 Run 快照

```text
schemaVersion
runID
seed
contentVersion
cardPoolVersion
balanceVersion
floorIndex
nodeID
runLevel
gold
partyHP/SP
temporaryCards
temporaryEquipments
temporarySkills
rewardQueue
visitedScenes
usedBossIDs
worldRuleSnapshot
lastTransactionID
```

卡牌生成时保存解析后的效果快照；装备使用副本实例；技能不能只保存 ID 后在读档时无条件读取最新模板。

## 5. 窗口与 UI 执行顺序

1. 先在现有 UI 38 增加肉鸽图片卡片和点击入口，普通四关卡按钮行为不改。
2. 新建 `GUI_RogueEntry`，只做开始/继续/放弃和队伍预览。
3. 新建 `GUI_RogueMap`，先用三个节点按钮，不做复杂路线动画。
4. 新建 `GUI_RogueReward`，先用固定测试卡验证暂停、二次确认、队列和误触屏蔽。
5. 新建 `GUI_RogueResult`，确认所有退出路径都调用 `RogueRunManager.finishRun/abortRun`。
6. 每个 UI 数据条目需加入 `asset/json/ui/data/`，对应脚本需加入 `Game/tsconfig.json`，并设置 `instanceClassName`/注册方式。

## 6. 地图执行顺序

首版新建并只填底层：

- 小型战斗图 A：近战通道。
- 小型战斗图 B：开阔区域。
- 商人/休整安全图。
- 大型 Boss 图。

每张图必须有地块、碰撞、玩家出生点、敌人出生点、胜负条件、进入事件和离开节点；可暂不做完整美术。不要直接改主线场景中的剧情对象和开关。

## 7. 第一阶段可运行切片

固定流程先跑通：

```text
UI 38 肉鸽卡片
  -> GUI_RogueEntry
  -> 小图 A
  -> 每击杀升级/奖励队列/三选一
  -> GUI_RogueMap（固定小图 B）
  -> 小图 B
  -> GUI_RogueMap（固定 Boss）
  -> Boss 图
  -> GUI_RogueResult
```

第一阶段暂不加入：随机路线、复杂商人库存、永久解锁、多个 Boss 词缀和复杂动态地图。

## 8. 必须提前防止的疏忽

- 普通 `calcHitReward` 先写金币/经验/背包，再判断肉鸽会造成主线污染；分支必须提前。
- 只保存技能/装备 ID 会导致主干改数值后旧 Run 漂移；必须保存副本或定义快照。
- 只在胜利时恢复 `fullStateWhenBattleStart` 不够，失败、放弃、读档失败和异常恢复都要处理。
- 复用 `14022` 可能重复结算；必须使用事务 ID/`rogueHandled`。
- 新脚本不加入显式 `tsconfig files` 会导致实际没有编译。
- 只创建 UI JSON 不会自动调用项目层脚本；需要完成 UI 类注册和事件绑定。
- 动态扫描新增内容时必须过滤剧情专用、敌方专用、资源缺失和未平衡内容。
- 新增职业/角色不能复制旧初始队伍副本；应按当前角色数据库和职业 ID 动态初始化。
- 肉鸽商店不能直接扣主线金币，肉鸽卡牌不能直接进入主线背包。
- 奖励界面必须在当前行动链完成后打开，不能在死亡回调中重入 UI。

## 9. 开工前验收门槛

在开始大规模内容制作前，先完成以下最小验证：

1. 普通关卡进入/战斗/胜利，确认没有 `RogueRunState`、卡牌或临时金币。
2. 新建 Run，击杀一个敌人，确认只 Run 等级 +1，主线经验不变。
3. 生成三卡但不确认，保存/读档后确认没有提前获得奖励。
4. 确认一张装备卡，验证只进入 Run 临时背包且能在战斗中使用。
5. 修改主干技能数值后，新 Run 使用新值，旧 Run 按快照继续。
6. 失败、放弃、普通存档读取后确认 `active=false` 且全局规则恢复。
7. 重复触发胜利回调，确认只结算一次。
8. 新增带 `rogueEnabled` 的技能/装备/职业后，新 Run 能扫描到；未标记内容不出现。

## 11. 完成定义

只有同时满足以下条件才算第一阶段完成：

- 普通关卡回归测试通过。
- 肉鸽入口可开始/继续/放弃。
- Run 可保存/恢复且版本字段存在。
- 击杀升级和三选一卡牌只在 Run 生效。
- 装备/技能奖励只存在于 Run 临时容器。
- 固定两张小图和一张 Boss 图可完整通关。
- 所有退出路径恢复世界规则。
- 新主干内容可通过标签进入新 Run。
- TypeScript 构建和移动/桌面 UI 基础测试通过。
