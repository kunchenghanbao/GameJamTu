# 物品与消耗品扩充设计

## 1. 目标与现状

当前物品模块位于 `asset/json/custom/customModule/1/`，已有 6 个数据文件：

| ID | 名称 | 当前用途 |
| ---: | --- | --- |
| 1 | 指引信 | 剧情道具，不进入肉鸽消耗品池 |
| 2 | 生命回复药剂 | 回复 100 HP |
| 3 | 魔法回复药剂 | 回复 100 SP |
| 4 | 解毒剂 | 解除中毒 |
| 5 | 水晶球 | 立即向前瞬移 3 格 |
| 6 | 未命名 | 空白占位，无属性且未发现直接引用 |

本次建议把空白 `ID 6` 作为第一个新物品，并新增 `ID 7-25`，共补充 20 个物品。实施后数据库将有 25 个已命名物品，编号连续，不覆盖已有有效内容。

设计原则：

- 单个物品效果简单明确，不引入合成、词条或多级强化。
- 回复、解除状态和普通增益优先使用现有 `Module_Item` 字段落地。
- 特殊战术物品由 `RogueSkillSynergySystem` 集中处理，不把复杂逻辑塞进物品 JSON 或序列化事件。
- 普通补给可用于主线；涉及锁血、元素反应和血魔流的物品暂时只在肉鸽模式出现。
- 战斗奖励一次最多出现 1 个消耗品，避免消耗品挤占技能和装备奖励。

## 2. 字段约定

沿用现有 `Module_Item` 字段：

| 字段 | 约定 |
| --- | --- |
| `isUse` | 20 个新物品均为 `true` |
| `isConsumables` | 20 个新物品均为 `true` |
| `useType` | `0` 任何场合、`1` 仅非战斗、`2` 仅战斗 |
| `isSingleTarget` | 回复与净化物品为友方单体；战术范围物品以使用者为中心 |
| `costActionPower` | 即时急救和解除控制不消耗行动力；持续回复、增益和攻击型物品消耗行动力 |
| `recoveryHP` / `recoverySP` | 只填写固定回复值 |
| `addStatus` / `removeStatus` | 直接复用现有状态 ID |
| `callEvent` | 保持为空；特殊效果由肉鸽运行时按物品 ID 集中处理 |

稀有度只控制获得来源和肉鸽权重，不需要扩展物品数据结构：

| 稀有度 | 肉鸽基础权重 | 出现规则 |
| --- | ---: | --- |
| 普通 | 15 | 第 1 关起可出现 |
| 稀有 | 8 | 第 2 关起可出现 |
| 传说 | 3 | 第 4 关起可出现，Boss 奖励权重提高 |

## 3. 新增物品清单

| 7 | 强效生命药剂 | 稀有 | 任何 / 消耗 | 为友方单体回复 220 HP。 | `recoveryHP=220` |

| ID | 名称 | 稀有度 | 场合 / 行动力 | 效果 | 落地方式 |
| ---: | --- | --- | --- | --- | --- |

| 18 | 魔力药剂 | 普通 | 仅战斗 / 消耗 | 魔力提高 25%，持续 4 回合。 | `addStatus=[10]` |
| 19 | 守护药剂 | 稀有 | 仅战斗 / 消耗 | 物理防御和魔法防御提高 100%，持续 3 回合。 | `addStatus=[12,14]` |

力量与魔力药剂服务普通构筑，守护与疾风药剂用于临时应对精英和 Boss，狂战药剂保留明确的高收益、高风险取舍。

### 3.4 肉鸽战术类（ID 22-25）

| ID | 名称 | 稀有度 | 场合 / 行动力 | 效果 | 落地方式 |
| ---: | --- | --- | --- | --- | --- |
| 22 | 护命露 | 传说 | 仅战斗 / 消耗 | 获得“不灭血印”。本场战斗受到下一次致命伤害时保留 1 HP，触发后移除；不能重复叠加。 | `addStatus=[29]`，复用锁血处理器 |
| 23 | 炎爆药瓶 | 稀有 | 仅战斗 / 消耗 | 对使用者周围 1 格敌人造成 60 点炎伤害并附加燃烧 2 回合。可引出后续元素爆炸。 | 集中运行时范围结算 |
| 24 | 冰雷结晶 | 传说 | 仅战斗 / 消耗 | 对使用者周围 2 格敌人造成 45 点雷伤害；命中冰结目标时按现有规则触发超导。 | `RogueSkillSynergySystem` |
| 25 | 血契秘药 | 传说 | 仅战斗 / 消耗 | 消耗当前 HP 的 20%，最低保留 1 HP，获得 2 层血怒与血域 2 回合。 | 集中运行时 + 状态 `27、28` |

战术物品共同限制：

- 只在 `RogueRunManager.active` 时生效并进入奖励池。
- 炎爆药瓶和冰雷结晶造成的伤害不能暴击、吸血或再次触发连锁反应。
- 护命露每个角色每场战斗最多生效一次；血印已触发时再次使用只消耗物品但不应产生效果，因此 UI 必须在不可生效时禁用。
- 血契秘药的扣血属于生命消耗，不触发反击、受伤事件或敌方击杀判定。

## 4. 获得方式与肉鸽奖励池

### 4.1 主线与商店

| 来源 | 建议物品 |
| --- | --- |
| 基础商店 | ID 2、3、4、6、12、13 |
| 高级商店 | ID 7-11、14、15、17-20 |
| 普通敌人掉落 | ID 6、12、13，低概率掉落 ID 17、18 |
| 精英敌人或宝箱 | ID 7-11、14、15、19、20 |
| 剧情或 Boss 奖励 | ID 16、21 |
| 肉鸽专属 | ID 22-25 |

主线不投放 ID 22-25，避免肉鸽临时状态和主线存档互相污染。

### 4.2 肉鸽奖励池

肉鸽池保留现有 ID 2、3、4，并加入 ID 6-25。ID 1 不加入；ID 5 水晶球建议作为稀有战术道具加入，权重为 8。

为避免 20 个新增物品抬高整个消耗品类别的出现率，抽取应先决定奖励大类，再在大类内部按权重选具体物品：

```text
先抽奖励类型：技能 / 装备 / 消耗品
  -> 若抽到消耗品，再按普通 15、稀有 8、传说 3 抽物品
  -> 同一组三选一最多出现 1 个消耗品
```

建议消耗品类别在普通小关奖励中的总占比为 15%，精英或 Boss 奖励中提高到 20%。传说物品从第 4 关开始出现，Boss 关传说权重翻倍。

消耗品奖励每次给予 1 件；战地绷带、凝血粉、解燃露可一次给予 2 件。物品允许重复获得，不转换金币。

## 5. 状态复用与前置修正

本方案不新增状态 ID，复用下列现有状态：

| 用途 | 状态 ID |
| --- | --- |
| 持续生命 / 魔力回复 | 7、21 |
| 普通属性增益 | 8、10、12、14、16 |
| 狂战风险增益 | 22 |
| 血魔联动 | 27、28、29 |

实施前需要修正状态 21“恢复魔力”的说明文字：当前数据实际按 SP 恢复结算，但 `intro` 错写成“恢复生命值”。修正说明即可，不调整其数值逻辑。

## 6. 图标资源方案

现有物品图标均为 `48 x 48` PNG。实施时优先复用已有图标变体，缺少的图标再单独绘制，保持现有像素幻想 RPG 的轮廓、明暗和透明背景，不照搬外部作品。

建议按视觉类别统一识别：

| 类别 | 视觉特征 |
| --- | --- |
| 生命 / 魔力 | 红色、蓝色药液，瓶型区分普通与强效 |
| 混合 / 持续回复 | 双层药液、叶片或水滴符号 |
| 状态解除 | 粉末、符纸、香炉、白色圣水瓶 |
| 属性增益 | 剑、法杖、盾、羽翼附着在药瓶标签上 |
| 战术物品 | 血印、火焰、冰雷裂纹等高对比核心符号 |

20 个新增物品均使用独立绘制的原创图标，同时保留高分辨率生成源图和 `48 x 48` 游戏用透明 PNG。

## 7. 实施顺序

1. 将空白 `cm6.json` 填为战地绷带，新增 `cm7.json` 至 `cm25.json`。
2. 更新 `customModuleDataList1.json` 的 ID 与中文名称映射。
3. 修正状态 21 的说明文字，配置所有可直接落地的回复、增益和净化物品。
4. 在 `RogueSkillSynergySystem` 中集中处理 ID 22-25，并接入现有锁血、超导和血魔逻辑。
5. 补齐或绘制 `48 x 48` 透明背景图标。
6. 将物品加入商店、掉落和肉鸽二级奖励池。
7. 增加数据校验，检查 ID、名称、图标、说明、使用场合和奖励池覆盖。

## 8. 验收标准

1. 物品模块共有 25 个已命名数据，ID `1-25` 连续且不存在空白记录。
2. 20 个新增物品均有非空名称、说明和 `48 x 48` 图标。
3. 回复类正确限制最大 HP/SP，不产生溢出异常。
4. 净化物品只移除说明中列出的负面状态，不清除正面状态。
5. 不消耗行动力的物品使用后仍可正常行动；消耗行动力的物品不能在同回合继续攻击或施法。
6. 护命露、冰雷结晶和血契秘药只在肉鸽模式生效，Run 结束后不污染主线数据。
7. 炎爆药瓶可以提供燃烧，后续非炎攻击可正常触发元素爆炸。
8. 冰雷结晶命中冰结目标时只触发一次超导，不产生递归反应。
9. 一组三选一最多出现 1 个消耗品，普通小关的消耗品卡总体占比接近 15%。
10. 构建、肉鸽测试及物品数据校验全部通过。
