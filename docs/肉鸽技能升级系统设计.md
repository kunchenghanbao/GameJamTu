# 肉鸽技能升级系统设计

## 1. 目标

为肉鸽模式增加局内技能升级功能，解决当前重复技能只能转换为 50 金币的问题。

核心规则：

- 技能首次获得时为 `Lv.1`。
- 再次选择同一角色已经拥有的同名技能时，升级为 `Lv.2`。
- 第三次选择时升级为 `Lv.3`，达到满级。
- 满级后再次抽到该技能，转换为金币或重新抽取，不继续无限叠加。
- 所有升级只在当前肉鸽 Run 内生效，结束、失败或中止后不影响主线技能。
- 升级效果固定，不随机词条，玩家可以在奖励卡上直接看到下一级效果。

## 2. 升级流程

```text
未拥有技能
  → 选择奖励
  → 学习技能 Lv.1

已拥有 Lv.1
  → 再次选择同一技能
  → 升级为 Lv.2

已拥有 Lv.2
  → 再次选择同一技能
  → 升级为 Lv.3

已拥有 Lv.3
  → 不再升级
  → 转换为 100 金币
```

奖励卡显示规则：

| 当前状态 | 卡牌标题 | 卡牌说明 |
| --- | --- | --- |
| 未拥有 | `血刃` | 显示 Lv.1 完整效果 |
| 已有 Lv.1 | `血刃 Lv.2` | 只显示本次提升内容 |
| 已有 Lv.2 | `血刃 Lv.3` | 显示最终机制强化 |
| 已有 Lv.3 | 不进入普通技能候选 | 卡池不足时才显示“满级转化：100 金币” |

## 3. 等级设计原则

每个技能只升级两次：

- `Lv.1`：数据库中的基础技能。
- `Lv.2`：主要提升数值、消耗、冷却或持续时间。
- `Lv.3`：增加一个容易理解的机制强化。

数值控制：

- 主动伤害技能 Lv.2 通常提高约 15% 属性倍率。
- 大招 Lv.2 通常降低消耗或减少 1 回合 CD，不同时获得两项大幅提升。
- 状态技能 Lv.2 通常增加持续时间或强化数值。
- 被动技能 Lv.2 提高原效果，Lv.3 扩大触发条件或增加有限次数。
- Lv.3 不应彻底消除技能原本的风险。例如血魔技能升级后仍然需要扣血。

## 5. 数据结构

不建议直接给 `Module_Skill` 增加永久等级字段，因为数据库技能、角色技能副本和主线技能共用该结构，容易污染主线。

在 `RogueRunState` 中新增独立记录：

```ts
interface RogueSkillUpgradeRecord {
    actorIndex: number;
    skillID: number;
    level: number; // 1-3
}

skillUpgrades: RogueSkillUpgradeRecord[];
```

查找键为：

```text
actorIndex + skillID
```

同一个技能由不同角色获得时分别升级，不共享等级。

记录示例：

```json
{
  "actorIndex": 0,
  "skillID": 41,
  "level": 2
}
```

## 6. 升级效果存储方式

建议新增 `RogueSkillUpgradeSystem.ts`，在代码中维护升级定义：

```ts
interface RogueSkillUpgradeDefinition {
    skillID: number;
    level2: RogueSkillUpgradeEffect;
    level3: RogueSkillUpgradeEffect;
}

interface RogueSkillUpgradeEffect {
    damageMultiple?: number;
    costSP?: number;
    totalCD?: number;
    rangeBonus?: number;
    areaBonus?: number;
    statusValue?: number;
    mechanic?: string;
}
```

处理规则：

1. 玩家获得技能时保存一份数据库基础技能副本。
2. 根据 `skillUpgrades` 中的等级，从基础值重新计算当前技能属性。
3. 禁止在当前值上重复相加，避免读档后倍率不断增长。
4. Lv.3 的特殊机制由升级系统读取等级后处理。
5. 存档只保存技能 ID 和等级，不保存可执行脚本。

例如血刃：

```text
数据库基础倍率：125
Lv.1：125
Lv.2：145
Lv.3：145，并解锁低生命目标额外血怒
```

## 7. 奖励系统修改

当前重复技能在 `RogueRewardResolver` 中直接转换为 50 金币，需要改成：

```text
角色未拥有技能
  → 学习技能
  → 建立 Lv.1 记录

角色已拥有技能且等级 < 3
  → 不再调用 learnSkillBySkillID
  → 等级 +1
  → 重新应用升级后的技能属性

角色技能已满级
  → 转换 100 金币
```

奖励卡快照需要增加：

```ts
upgradeTargetLevel: number;
upgradeDescription: string;
```

确认奖励时仍沿用现有事务 ID，避免重复点击导致一次卡牌升两级。

## 8. UI 显示

### 奖励界面

- 卡牌标题显示 `技能名 Lv.2` 或 `技能名 Lv.3`。
- 说明只展示本次升级变化，例如：`伤害倍率 125% → 145%`。
- 满级技能原则上从候选池移除。

### 技能列表

- 技能名称后显示当前等级，例如 `血刃 Lv.2`。
- 技能说明显示升级后的最终数值。
- Lv.3 特殊效果使用单独一行：`满级：攻击低生命目标时额外获得血怒。`

不需要为三个等级分别制作新图标。原技能图标右下角叠加 `I/II/III` 或 `Lv.1/Lv.2/Lv.3` 即可。

## 9. 技能范围与排除项

本系统覆盖玩家可用技能 ID `1-60` 和可学习敌方技能 ID `1001-1018`。肉鸽奖励池需要从当前只有少量原始技能的状态扩展为完整登记，并按角色职业过滤：

- 剑士主要出现 1-5、20-26 及通用状态技能。
- 魔法师主要出现 6-9、27-29、49-57 及通用状态技能。
- 弓箭手主要出现 10-12、29-31 及通用状态技能。
- 医师主要出现 13-17、32-34 及通用状态技能。
- 格斗家主要出现 18-26、41-48 及通用状态技能。
- 召唤师主要出现 32、35-40 及通用状态技能。
- 元素技能可以跨职业出现，但非对应职业的基础权重降低 50%。
- 敌方技能根据效果加入对应职业：近战技能进入剑士/格斗家池，法术进入魔法师池，毒与远程技能进入弓箭手池，控制进入医师/召唤师池，召唤技能进入召唤师池。
- 每次三选一最多出现一张敌方技能，避免原职业技能被大量稀释。
- 敌方技能基础权重为同稀有度玩家技能的 60%。

以下内容不进入重复升级系统：

| ID 范围 | 类型 | 处理方式 |
| --- | --- | --- |
| 1019-1030 | 未命名敌方技能槽 | 数据不完整，不进入奖励池 |
| 2001-2006 | 职业普通攻击 | 跟随角色基础成长，不作为独立奖励 |
| 3001-3014 | 角色固有被动 | 默认不抽取；未来若作为奖励，需要单独设计升级表 |

这样原本已经学习的十字斩、火球术、毒箭连射、自然治愈等技能，以及肉鸽中学到的隐身、暗蚀术、狂雷等敌方技能，都可以通过重复奖励直接升到 Lv.2/Lv.3，而不是继续转换金币。

## 10. 存档与隔离

- `skillUpgrades` 随肉鸽 Run 存档。
- 读档后先恢复临时技能，再按等级重新计算升级效果。
- 完成、失败或中止 Run 时清除升级记录。
- 不修改主线角色技能数据库实例。
- 旧版肉鸽存档没有该字段时，初始化为空数组；已拥有的 ID 1-60、1001-1018 技能按 Lv.1 处理。

建议将肉鸽存档 Schema 从当前版本递增一次，并保留旧存档迁移逻辑。

## 11. 验收标准

1. 首次获得新技能后显示为 Lv.1。
2. 同一角色重复获得技能时依次升级为 Lv.2、Lv.3。
3. 不同角色拥有同一技能时等级互不影响。
4. Lv.3 满级技能不会继续提高数值。
5. 满级重复技能转换为 100 金币，且只结算一次。
6. 伤害、SP、CD、范围和状态持续时间与升级表一致。
7. ID 1-60、1001-1018 的 Lv.3 特殊机制均有独立测试。
8. 保存并读取 Run 后技能等级和最终效果不变，不发生重复叠加。
9. 旧肉鸽存档能够迁移，已有新技能按 Lv.1 处理。
10. Run 结束、失败或中止后，主线技能恢复原始状态。
